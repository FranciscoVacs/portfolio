# Rediseño visual — Plan de Implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Adoptar el lenguaje visual del portfolio de referencia (github.com/urstruelysv/portfolio) y eliminar el modo oscuro.

**Origen:** pedido explícito de Francisco el 2026-08-10: *"me gustaría que uses solo el diseño de este portfolio... me gustan las animaciones que tienen y como está distribuido al igual que la tipografía y los colores. que no tenga opción de dark-mode."*

**Architecture:** El contenido, las rutas, la internacionalización y los tests de comportamiento no cambian. Este plan toca únicamente la capa de presentación: tokens de color, tipografía, tratamiento de tarjetas, navegación y animaciones de entrada.

## Qué se observó en la referencia

Clonada y leída en detalle. Sus decisiones visuales concretas:

| Elemento | Referencia | Nuestro estado hoy |

| Paleta | Variables HSL estilo shadcn (`--background: 0 0% 100%`, `--foreground: 240 10% 3.9%`, `--secondary: 240 4.8% 95.9%`, `--border: 240 5.9% 90%`) | Hex propios |

| Etiquetas de stack | Píldora rellena: `rounded-full px-2 py-1 text-xs font-medium bg-gray-100 text-gray-700 hover:bg-gray-200 transition-colors` | Píldora con borde, sin relleno |

**Nota sobre un cambio de criterio:** durante el diseño original Francisco descartó explícitamente "tarjetas con gradiente que sigue al mouse". La referencia tiene ese efecto en una versión mucho más contenida, y al verlo en contexto lo pidió. Se implementa la versión de la referencia, no la del template original, que era considerablemente más agresiva.

## Global Constraints

- **No hay modo oscuro.** Ni toggle, ni clase `.dark`, ni variantes `dark:`, ni `next-themes` en `package.json`.
- Se conserva todo lo demás: rutas, contenido, internacionalización, metadatos, sitemap.
- **Ningún test de comportamiento existente puede romperse.** Si un test falla por un cambio visual legítimo (por ejemplo el del toggle de tema, que deja de existir), se elimina o ajusta ese test y se documenta; los demás deben seguir pasando sin tocarse.
- Tailwind CSS 4: la configuración va dentro del CSS con `@theme`. No existe `tailwind.config.ts`. **La referencia usa Tailwind 3 con `tailwind.config.ts`: hay que traducir sus tokens a la sintaxis de Tailwind 4, no copiar su config.**
- Next.js 16: `params` y `searchParams` son Promesas.
- Los componentes sólo llevan `'use client'` si lo necesitan de verdad. Las animaciones y los efectos de cursor lo requieren; el resto no.
- **El prerenderizado estático de `/en`, `/es`, `/en/fav`, `/es/fav`, `/en/cv` y `/es/cv` debe conservarse.** Verificar en la tabla de rutas de `next build`.
- Alias `@/*` → `src/*`. Commits en español con prefijo convencional.
- Biome formatea con comillas dobles: escribir y luego `npm run lint:fix`.

- [ ] **Step 3: Crear la tarjeta con efecto de cursor**

`src/components/ui/HoverCard.tsx`. Es cliente porque necesita estado de mouse. La sombra sigue al cursor con un desplazamiento máximo de 6px y el resplandor es un gradiente radial azulado suave, tal como la referencia:

```tsx
"use client";

import { useRef, useState } from "react";

export function HoverCard({ children }: { children: React.ReactNode }) {
  const ref = useRef<HTMLDivElement>(null);
  const [pos, setPos] = useState({ x: 0, y: 0 });
  const [hovered, setHovered] = useState(false);

  function onMouseMove(event: React.MouseEvent) {
    const rect = ref.current?.getBoundingClientRect();
    if (!rect) return;
    setPos({ x: event.clientX - rect.left, y: event.clientY - rect.top });
  }

  function shadow() {
    const rect = ref.current?.getBoundingClientRect();
    if (!hovered || !rect) {
      return "0 4px 6px -1px rgb(0 0 0 / 0.1), 0 2px 4px -1px rgb(0 0 0 / 0.06)";
    }
    const offsetX = (pos.x - rect.width / 2) / (rect.width / 2);
    const offsetY = (pos.y - rect.height / 2) / (rect.height / 2);
    const intensity = Math.min(1, Math.hypot(offsetX, offsetY) * 0.8);
    return `${-offsetX * 6}px ${-offsetY * 6}px ${12 + intensity * 4}px rgb(0 0 0 / ${0.08 + intensity * 0.06})`;
  }

  return (
    <div
      ref={ref}
      onMouseMove={onMouseMove}
      onMouseEnter={() => setHovered(true)}
      onMouseLeave={() => setHovered(false)}
      className="relative overflow-hidden rounded-xl border border-border bg-background p-6 transition-all duration-300"
      style={{ boxShadow: shadow() }}
    >
      {hovered ? (
        <div
          aria-hidden
          className="pointer-events-none absolute inset-0 transition-opacity duration-500"
          style={{
            background: `radial-gradient(600px 600px ellipse at ${pos.x}px ${pos.y}px, rgb(148 181 252 / 0.15), rgb(147 197 253 / 0.12), transparent 60%)`,
            filter: "blur(1px)",
          }}
        />
      ) : null}
      <div className="relative">{children}</div>
    </div>
  );
}
```

- [ ] **Step 2: Crear el componente de entrada**

`src/components/ui/FadeIn.tsx`. La referencia usa `opacity: 0, y: -10` → `opacity: 1, y: 0`, con variantes escalonadas. Acá se expone un `delay` para escalonar sin acoplar los componentes entre sí:

```tsx
"use client";

import { motion, useReducedMotion } from "framer-motion";

export function FadeIn({
  children,
  delay = 0,
}: {
  children: React.ReactNode;
  delay?: number;
}) {
  const reduced = useReducedMotion();

  if (reduced) return <>{children}</>;

  return (
    <motion.div
      initial={{ opacity: 0, y: 8 }}
      whileInView={{ opacity: 1, y: 0 }}
      viewport={{ once: true, margin: "-40px" }}
      transition={{ duration: 0.4, delay, ease: "easeOut" }}
    >
      {children}
    </motion.div>
  );
}
```

`useReducedMotion` no es opcional: quien tenga activada la preferencia de movimiento reducido del sistema recibe el contenido sin animación, no una animación más lenta.
